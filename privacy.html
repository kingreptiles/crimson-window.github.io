This website

This is a static information website hosted on GitHub Pages. It has no account registration, chat service, payment form, advertising, or site-added analytics. It does not add tracking cookies or load third-party fonts.

GitHub may process technical visit information as the hosting provider. See GitHub’s privacy statement. Clicking an email link opens your email application; any message you send is handled by the relevant email services.

If you contact us

If you email Crimson Window, the message includes your address and whatever information you choose to provide. Send only what is needed to answer your question. Please do not send API keys, passwords, full payment details, illegal images, or an entire private conversation.

Privacy questions can be sent to uta.cornelc@gmail.com.

How development builds handle data

The app is not publicly downloadable. For people using a development build, the current implementation distinguishes:

  • Device data: local conversations, profiles, custom instructions, and provider settings are stored on the device, with account-separated local databases.
  • Account data: the backend holds account and creator-profile information, age-access information, and service usage records.
  • AI requests: relevant messages, profile context, character/persona information, instructions, summaries, and pinned content pass through the backend to the selected AI provider. Local chat storage does not mean chats stay on-device during generation.
  • Optional cloud features: eligible accounts can sync conversation content and related snapshots. Private cloud storage and public publication are different features.
  • Public content: published characters, personas, shared memories, comments, and reactions are available to users with the relevant access. Sharing a memory publishes the selected copy.
  • Support and moderation: reports may include contact information, explanations, links, and preserved character content for review.

Providers and API keys

The backend supports AI services including Groq, OpenAI, and OpenRouter, depending on configuration. A selected package may try another configured model/provider after a failure. Relevant conversation context can therefore be processed by more than one provider during retries.

A user-owned OpenAI key is stored using platform-provided protected storage and sent to the backend when needed for model listing or generation. It is not part of ordinary conversation cloud synchronization. Provider privacy practices, retention, and charges are separate from this website.

Learn more from Groq, OpenAI’s API data controls, and OpenRouter. Do not treat a fictional chat as a confidential channel for sensitive real-world information.

Before a public release

These are development notes, not a complete privacy notice for a released service. Operator details, service-specific retention information, provider arrangements, and the process for exercising applicable privacy rights will need to be published with the public service.
